# BeerShop CRM 1.0 (платформа 4.2.0)

Вхід: `/crm` або посилання **BeerShop CRM** в `/manage`. Використовуйте чинний `BEERSHOP_ADMIN_TOKEN` із Render Environment. Не передавайте його в чат, URL, GitHub чи стороннім особам. У новій CRM токен живе лише в пам'яті вкладки; після перезавантаження потрібен повторний вхід.

## Перший випуск

- Замовлення: пошук за номером, ім'ям, телефоном або email; фільтри статусу, оплати, пріоритету та відповідального; сторінки по 25 записів.
- Нове замовлення: активні SKU із залишком, актуальна серверна ціна, перевірка очікуваної суми та ідемпотентний ключ. Товари резервуються тим самим транзакційним механізмом, що й на вітрині.
- Клієнти: контакти, останні 100 замовлень і нотаток, редагування контактів із захистом від перезапису паралельних змін. Старі замовлення зберігають початкові контакти покупця.
- Відповідальні: довідник імен, призначення, деактивація. **Це не облікові записи, не ролі й не окремі дозволи.** Всі користувачі чинного токена мають повний адміністративний доступ.
- Нотатки не редагуються й не видаляються; повтор того самого запиту не створює дубль. Зміни статусу, відповідального, оплати та доставки потрапляють до журналу.
- Оплата: лише ручна звірка реальної банківської виписки, точної суми UAH, номера рахунку і унікального ID транзакції. Автоматичне підтвердження не вмикається.
- Доставка: запис вже створеної ТТН, перевірка офіційним API за наявності `NOVA_POSHTA_API_KEY` або ручне підтвердження за кабінетом перевізника. Відправлення не створюються. Завершення потребує оплати й доставки.
- Просте скасування дозволене лише до оплати та реєстрації ТТН. Повернення грошей/товару потребують окремого процесу, якого цей випуск не реалізує.

KeyCRM для власної CRM не потрібна. Наявні інтеграції залишено без зміни прапорців: `KEYCRM_SYNC_ENABLED=0`, `PRIVATBANK_READ_ENABLED=0`. Не вмикайте передачу даних або банківський доступ без належної авторизації.

## Дані й оновлення

Додаються лише `crm_customers`, `crm_managers`, `crm_order_details`, `crm_notes`. Каталог, SKU, ціни, залишки та попередні замовлення не переписуються під час деплою. PostgreSQL DDL зафіксовано в `migrations/0042_crm.sql`; поточний bootstrap `Base.metadata.create_all` створює еквівалентну схему. Повноцінна система версійних міграцій Alembic залишається окремим завданням.

Індексація історичних замовлень виконується при старті, вході та оновленні CRM. Дати, яких раніше не було в базі, не вигадуються. Нові замовлення й картки клієнтів створюються в одній транзакції.

Автоматичне зв'язування клієнтів потребує одночасного збігу нормалізованих email і телефону. Збігу лише телефону недостатньо. Зміна контактів може призвести до окремої картки при наступному замовленні зі старими контактами; автоматичного злиття немає.

Приватний резервний JSON у `/manage` включає нові таблиці. Це експорт із персональними даними, а не реалізований процес аварійного відновлення. Потрібні окремі перевірки відновлення, персональні входи/ролі, 2FA, політика зберігання даних, захист від зловживань і аудит безпеки перед реальними продажами.

## Перевірки

`pytest -q` перевіряє API, авторизацію, транзакції, конфлікти версій, повторні запити, ізоляцію магазинів та міграцію зі старої схеми зі збереженням 100 товарів. Зовнішні провайдери в тестах заблоковані або замінені фікстурами.

`tests/crm_browser.cjs` запускається через Node із встановленим `playwright` і Chromium. Потрібен окремий локальний сервер із синтетичною базою та фіксованим тестовим курсом НБУ. Скрипт відмовляється працювати з нелокальним URL, створює лише локальні фікстури та не звертається до провайдерів. Параметри: `CRM_TEST_URL`, `CRM_TEST_TOKEN`, `CHROMIUM_PATH`. Покрито створення замовлення, призначення, екранування нотаток, ручні оплату/доставку, завершення, контакти, пошук і ширини 1366/390/320 px.

Локальний сервер-фікстура (окремий термінал, порожній тимчасовий файл БД; тестовий токен не використовувати на Render):

```bash
env -u BEERSHOP_PERSISTENT_DATABASE_URL PYTHONPATH=. DATABASE_URL=sqlite:////tmp/beershop-crm-browser.db BEERSHOP_ADMIN_TOKEN=tttttttttttttttttttttttttttttttttttttttt uvicorn crm_preview:app --app-dir tests --host 127.0.0.1 --port 8018
```

Потім `node tests/crm_browser.cjs`. Скриншоти зберігаються в `/tmp/crm-*.png`.

Жодних тестових покупців, оплат або ТТН у live-середовище не додається.
