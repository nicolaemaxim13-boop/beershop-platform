# BeerShop v9 — staging-аудит готовності до продажів

**Стан:** тестова GitHub-гілка \`staging/beershop-v9-sales-readiness-audit\`.
**Production:** гілка \`main\` і чинний Render \`beershop-preview\` залишаються без змін.
**Немає:** реальних платежів, нових платних інфраструктурних компонентів, копіювання реальних замовлень до тестової БД.

## Що реалізовано

- \`GET /api/admin/v9/readiness\` — захищений лише для читання. Відповідь **не містить** персональних даних покупців, номерів рахунків, секретів або ідентифікаторів транзакцій.
- Вкладка **Готовність v9** в \`/manage\`. Можна переглянути вимоги до безпеки, цін, складу, реквізитів IBAN, відновлення та правових документів.
- Перевірка структури **українського IBAN** (29 символів, \`UA\` + цифри, ISO 13616 mod 97). Це **не перевірка власника рахунку, реквізитів банку або зарахування коштів**; додаткова перевірка обов'язкова.
- Якщо IBAN або назва отримувача некоректні, формування нового рахунку через \`/api/admin/orders/{id}/invoice\` завершується 503, а не показом хибного рахунку.
- Заголовки захисту \`X-Frame-Options\`, \`Referrer-Policy\`, \`X-Content-Type-Options\`, \`Permissions-Policy\`. Адміністративні відповіді мають \`Cache-Control: private, no-store\`; HTTPS отримує HSTS. CSP із блокуванням inline-script **ще не встановлено**, оскільки наявна адмінпанель використовує inline JS.
- Два **опціональні** staging-перемикачі, вимкнені за замовчуванням:
  - \`BEERSHOP_V9_DISABLE_ORDER_CREATION=1\` повертає HTTP 503 для нових замовлень — не здійснює тестові продажі.
  - \`BEERSHOP_V9_REQUIRE_QUOTE_TOTAL=1\` відмовляє HTTP 428, коли покупець не підтвердив \`expected_total\`. Існуючі браузери, які передають \`expected_total\`, працюють без змін.
- Всі API-тести виконуються локально на GitHub Actions у **SQLite або PostgreSQL з синтетичними даними**, не в Neon production.

## Важливі реальні блокери

1. **Власний рахунок та договір ФОП:** IBAN-перевірка підтверджує лише формат і контрольну суму. Дані банку, податковий режим і документальна відповідність залишаються обов'язком оператора.
2. **Ціни:** ручна валютна політика має бути актуальною (до 24 год) та явно активованою. Офіційний курс НБУ не дорівнює купівельному курсу банку. Формула не покриває ЄСВ, повернення, пакування та інші фіксовані витрати.
3. **Фізичний склад:** \`variants.stock\` не є доказом реально доступного товару. Підтвердити залишки в постачальника, оформити перерахунок і звірити всі незавершені резерви.
4. **Безпека:** персональні облікові записи, ролі, MFA, централізовані rate limits, моніторинг та незалежний аудит. Один спільний адмінтокен не підходить для команди.
5. **Дані:** версійні міграції Alembic, зашифроване резервне копіювання та регулярний тест відновлення. Поточний JSON-експорт недостатній.
6. **Операції та законодавство:** договір із доставкою, процедура повернень та фіскалізації, публічна оферта, політика приватності, документи продавця, консультація бухгалтера та юриста.
7. **Платежі:** автоматичної звірки банківської виписки немає; поточне ручне підтвердження в CRM не є перевіркою API банку, не виконувати дій із реальними грошима в staging.

## Перевірка staging

Створити pull request із гілки v9 в \`main\` у **draft**-стані. CI перевіряє код, API, сторінку аудиту, IBAN, безпечні перемикачі й Playwright на ізольованій БД.

Для ручного запуску в окремому середовищі, **не на виробничому Render**:

\`\`\`bash
export DATABASE_URL=sqlite:////tmp/beershop-v9-staging.db
unset BEERSHOP_PERSISTENT_DATABASE_URL
export BEERSHOP_ADMIN_TOKEN="REPLACE_WITH_LONG_RANDOM_STAGING_ONLY_SECRET"
export BEERSHOP_V9_DISABLE_ORDER_CREATION=1
export BEERSHOP_V9_REQUIRE_QUOTE_TOTAL=1
pytest -q tests/test_readiness_v9.py
\`\`\`

\`GET /api/admin/v9/readiness\` і діагностика схеми читають БД, але не змінюють ціни, склади, клієнтів, замовлення, платежі чи експортовані файли.

**Критерій випуску:** ніякого автоматичного merge або deploy на production за результатами цих тестів. Майбутній go-live потребує окремої перевірки всіх P0 ризиків, достовірних реквізитів, фізичних залишків, юридичних вимог і явного рішення власника.
