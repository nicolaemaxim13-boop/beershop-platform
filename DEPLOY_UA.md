# BeerShop — тестове розгортання (не production)

## Що готово
- Dockerfile для FastAPI та статичної вітрини.
- `render.yaml` для Render Blueprint: вебсервіс + PostgreSQL.
- `/api/health` для перевірки доступності.
- Секрет `BEERSHOP_ADMIN_TOKEN` генерується в середовищі Render; не записуйте його в Git.

## Запуск через GitHub + Render
1. Створіть **приватний** GitHub-репозиторій та завантажте в нього **вміст цієї папки**, без файлів `.env` і `*.db`.
2. У Render виберіть **New → Blueprint**, під'єднайте репозиторій та підтвердьте створення сервісів із `render.yaml`. У Blueprint вибрані безкоштовні тарифи `free`. Render Free Postgres спливає через 30 днів, а завантажені у локальне файлове сховище фото можуть зникнути після перезапуску або нового деплою. Перед створенням ресурсів перевірте екран витрат Render.
3. Після деплою відкрийте адресу вебсервісу Render і перевірте `/api/health`, `/` та `/manage`.
4. У Render Environment знайдіть `BEERSHOP_ADMIN_TOKEN` і використовуйте його тільки в захищеній адмінпанелі. Не публікуйте його.
5. Тримайте тестову вітрину закритою для реальних клієнтів до завершення аудиту.

## Критичні обмеження
- Немає справжніх облікових записів адмінів, 2FA, rate limiting, журналу аудиту, міграцій Alembic, резервного копіювання/відновлення з тестом, моніторингу.
- `Base.metadata.create_all()` не замінює міграції. Не оновлюйте схему живої бази без міграцій і резервної копії.
- Для PostgreSQL слід окремо перевірити конкурентні замовлення та коректність резервування залишків.
- Не використовуйте систему для реальних оплат чи замовлень до тестування захисту персональних даних та юридичної відповідності.
- Публічний URL не створюється цим архівом автоматично: для цього потрібен ваш GitHub/Render-акаунт та підтвердження розгортання.


## Neon migration 3.3

На Render (`beershop-preview` → Environment) установіть приватну `BEERSHOP_PERSISTENT_DATABASE_URL` з URL Neon, який має `sslmode=require`. Залиште старий `DATABASE_URL`: він потрібний для першого копіювання Render → Neon. Дані перемикаються лише після успішної транзакційної перевірки. Ніколи не публікуйте секретні URL і не використовуйте базу іншого проєкту BTC Edge AI. Для статистики використайте в адмінпанелі вкладку «Резервні копії». Локальні фото потрібне перенести окремо.


## BeerShop 4.1 — ключі провайдерів

Підключення виконується тільки через захищені Render Environment variables: `KEYCRM_API_KEY`, `NOVA_POSHTA_API_KEY`. Відправлення реального замовлення у KeyCRM окремо керується прапорцем `KEYCRM_SYNC_ENABLED=1` (за замовчуванням вимкнено). В адмінпанелі відкрийте «Інтеграції 4.1»; без ключів усе залишається в safe/off режимі. Банк та ТТН створення наразі не автоматизовані. Усі конфігураційні секрети — тільки в Render. Не вставляйте їх у чат/репозиторій.
